# CLAUDE.md

This file provides guidance to Claude Code when working in this repository.

## Project Overview

A dashboard that displays:
1. Live PSO (Pakistan State Oil) retail fuel prices — Petrol and HSD (High Speed Diesel) — for Pakistan.
2. OGRA wellhead gas price notifications for Mari Energies Limited (Mari D&P Lease area) — benchmark/normal volume price (Rs./MMBTU) and incremental volume price (US$/MMBTU).
3. Mari Energies (MARI) share price, and its standalone trade receivables broken down by counterparty (SNGPL/SSGCL/refineries/others) per quarter, from its quarterly financial reports.
4. Pakistan's monthly oil import volumes (total petroleum + crude-only), from OCAC's primary Import/Export report.
5. Live Dubai Crude oil price and JKM LNG spot price (via OilPriceAPI) — the two benchmarks closest to what Pakistan actually pays for imported crude and spot LNG cargoes.
6. Six global oil benchmark prices in one tile — Arab Light, Oman (DME), Das, WTI, Brent, and OPEC Basket — scraped from oilprice.com's chart page.
7. Pakistan's IMF EFF + RSF program status — total disbursed, latest/next tranche, and the flagged power-sector circular debt risk.
8. Mari Energies' latest PSX disclosures/announcements (financial results, board meetings, and general news), scraped from PSX's own Data Portal.
9. Strait of Hormuz transit status (open/closed) as a small header badge, scraped from a live tracker site — flags the geopolitical risk to Pakistan's crude/LNG import routes.
10. PPIS (Pakistan Petroleum Information Service) sector news — E&P licence/lease/discovery notices — in the same scrolling-ticker style as the PSX Announcements tile.
11. Mari Energies' share of Pakistan's total weekly oil and gas production, as two donut charts, from PPIS's login-gated Upstream Activities portal.
12. A 6-month Brent oil price outlook as bear/base/bull scenario ranges (not a point forecast) — a synthesis of publicly published third-party forecasts and current news, explicitly not a Claude/Mari prediction or investment advice.

## Tech Stack

- Frontend: Next.js (App Router) + TypeScript + Tailwind CSS
- PSO data source: scraped server-side from https://psopk.com/en/fuels/fuel-prices (no API key needed, no public JSON API exists — prices are embedded in the page's server-rendered HTML)
- Mari/OGRA data source: scraped server-side from https://www.ogra.org.pk/well-head-gas-prices (HTML list of notification periods + PDF links). The actual PDFs are scanned gazette documents with no text layer, so prices are NOT OCR'd automatically — see Architecture below.
- Running locally for now; hosting to be decided later

## Setup

```
npm install
npm run dev
```

Then open http://localhost:3000

Requires a `.env.local` (gitignored, not committed) with:
```
OILPRICEAPI_KEY=<your free key from https://www.oilpriceapi.com/>
```
Without it, `/api/commodity-prices` returns a 500 and the Dubai Crude / JKM LNG tiles just won't render — everything else on the dashboard still works.

## Architecture

- `app/api/oil-prices/route.ts` — server route that fetches the PSO fuel-prices page HTML and regex-parses the Petrol (`PREMIER EURO 5`) and HSD (`HI-CETANE DIESEL EURO 5`) rows out of the price table, plus the "Effective From" date. Returns normalized JSON.
- `app/api/mari-gas-price/route.ts` — server route that fetches OGRA's well-head-gas-prices listing HTML and regex-parses the latest Mari notification's period label and PDF link, then checks whether that PDF currently returns 200 (OGRA's server frequently 500s on newer uploads). The actual benchmark/incremental figures come from `LAST_VERIFIED_MARI_PRICE`, a hardcoded constant in that file — update it (including `period`/`periodShort`) by hand whenever a newer notification is actually read (e.g. via Claude reading the PDF directly, since it's a scanned image with no text layer — `pdftotext` returns empty on these). The dashboard's "Mari Field Prices (…)" heading pulls its bracketed period from `periodShort`, so it updates automatically the next time this constant is verified and updated.
- `app/api/commodity-prices/route.ts` — server route that calls OilPriceAPI (`api.oilpriceapi.com/v1/prices/latest`, `Authorization: Token <OILPRICEAPI_KEY>`) for `DUBAI_CRUDE_USD` and `JKM_LNG_USD` in parallel via `Promise.allSettled`, so one commodity failing doesn't blank out the other. Returns normalized `{ oil, lng, error, fetchedAt, source }`.
- `app/api/global-oil-benchmarks/route.ts` — server route that fetches oilprice.com's `/oil-price-charts/` page HTML and regex-extracts 6 rows keyed by their stable `data-id` attribute (not by name — the page reuses blend names across sections): Arab Light (`4402`), Oman/DME (`48`), Das (`4397`), WTI (`45`), Brent (`46`), OPEC Basket (`29`). Returns `{ benchmarks: [...], currency, unit, fetchedAt, source }`.
- `app/api/psx-announcements/route.ts` — server route that fetches PSX's company page (`dps.psx.com.pk/company/MARI`) HTML and regex-extracts rows from all three "Announcements" tabs (Financial Results, Board Meetings, Others — general news/disclosures like corporate briefings land under "Others", not just financial-results transmissions), anchoring on each tab's `data-name` attribute then its `<tbody class="tbl__body">` block. Merges all three, sorts by date descending, returns the top 3 as `{ announcements: [{date, title, category, url}], fetchedAt, source }`.
- `app/api/ppis-news/route.ts` — server route that calls PPIS's own JSON API directly (`ppisonline.com/api/blogs?category=sector-news&limit=3`) rather than scraping markup — the news page's content loads client-side from this endpoint with nothing in the initial server HTML. `press-release` and `publications` categories are currently empty; only `sector-news` (E&P licence/lease/discovery notices) has content. Returns `{ news: [{date, title, category, url}], fetchedAt, source }` in the same shape as the PSX route so both feed the same `NewsTickerTile` component.
- `app/api/hormuz-status/route.ts` — server route that fetches `straits.live`'s homepage HTML and regex-extracts a plain-text share/SEO summary sentence embedded in the page (`Strait of Hormuz: Closed. Day 146 since closure. Brent $98.15 (-2.4%). War-risk 8.0x normal.`) rather than any CSS class, since that sentence is serialized inside a JS string literal with escaped quotes (`\"text\":\"...\"`) that shifts between page builds. Also grabs the `<span class="eyebrow">` timestamp. Returns `{ status: "open"|"closed", dayCount, brentPrice, brentChangePercent, warRiskMultiplier, asOf, fetchedAt, source }`.
- `app/page.tsx` — client dashboard: polls `/api/oil-prices` every 5 min (PSO cards + price history chart via Recharts), `/api/mari-gas-price` every 30 min (Mari gas price cards + OGRA status panel), `/api/mari-share-price` every 5 min, `/api/commodity-prices` every 30 min (Dubai Crude / JKM LNG tiles), `/api/global-oil-benchmarks` every 30 min (the 6-benchmark tile), `/api/psx-announcements` and `/api/ppis-news` every hour (both rendered via the shared `NewsTickerTile` vertical-scrolling-ticker component), and `/api/hormuz-status` every hour (the Hormuz badge). `RECEIVABLES_BY_QUARTER`, `OIL_IMPORTS_LAST_MONTH`, and `IMF_PROGRAM` are hardcoded constants (same manual-verification pattern as `LAST_VERIFIED_MARI_PRICE`) — update by hand when a newer quarterly report, OCAC monthly row, or IMF review is read.
- **KPI tile styling ("Power BI report" look) and the "full report" toggle** (`app/page.tsx`): all 10 KPI tile components (2 rows of 5, including `ProductionShareKpiTile`) share one `KPI_CARD_CLASS` constant (`rounded-sm border border-mari-gray-light bg-white p-3` — flat, hairline border, no shadow) instead of each hardcoding its own card classes; there is no longer a style toggle (an earlier "Classic/Executive" pill-card variant was tried and removed at the user's request in favor of a single dense, flat, report-canvas look). Grid gaps between tiles are `gap-1` (not `gap-4`) and section margins are tight (`mt-1`/`mt-2`), and the header/`<main>`/footer containers all use `max-w-[1800px]` (a report-canvas width) instead of the narrower `max-w-7xl` centered-web-page column. Status badges (`LiveBadge`, `StatusPill`, `HormuzStatusBadge`) are small flat `rounded-sm` chips, not the original `rounded-full` pill buttons. `showDetails` state (default `false`) still gates the Trade Receivables panel and the 5 detail panels below the KPI strip behind a "Show/Hide full report" button. This is an ongoing redesign (started 2026-07-26) moving the dashboard away from a "web page" feel toward a Power BI-style report canvas — expect further passes on typography scale, tile density, and possibly a dark canvas.
- **`MARI_PRODUCTION_SHARE`** (`app/page.tsx`) drives two places: the compact `ProductionShareKpiTile` (row 2 of the KPI strip, 10th tile — small `DonutRing`s at 64px plus, per commodity, the top-producer company/percent and the "Bal" (balance — national total minus Mari's volume, i.e. the rest-of-sector amount) and the full `ProductionShareDonut` pair (160px rings) in the "Mari Share of National Production" detail panel, shown via "Show full report". `topProducer` is each field's combined company total, summing a company's rows across the report's Northern + Southern region sections where it appears in both (e.g. OGDCL). Note gas's `topProducer` is Mari Energies itself (31.85%, ahead of OGDCL's 28.68%) — `ProductionShareStat` special-cases this to show "Mari is #1" instead of the redundant "Top: Mari Energies 31.8%". Sourced from PPIS's Upstream Activities portal (`ppisonline.com/upstream-activities`) — **login-gated, no public API**, so unlike everything else on this dashboard it cannot be polled by a server route. This is pulled by hand: the user logs into PPIS in the browser (their own account), Claude reads the two "Weekly Oil/Gas Production" PDFs from the Upstream Activities > Weekly Production category while that session is active, computes Mari's share and the top producer's combined total, and updates this constant — same manual-verification pattern as `LAST_VERIFIED_MARI_PRICE`, just gated by a login instead of a stale-PDF problem. **Do not attempt to automate the login itself** — PPIS uses a standard Supabase-backed auth (a `sb-ppisonline-auth-token` in localStorage containing an access + refresh token); extracting/persisting that token to enable unattended weekly automation was considered and explicitly rejected (the refresh token is equivalent to full account access, and the environment's own safety tooling blocked attempts to pull it out of the browser) — stick to the human-in-the-loop pattern: user logs in, Claude reads, nothing is stored between sessions. The report download flow itself (for reference, in case a future session needs to redo this manually): click into a category (e.g. "Oil Production") to list documents, click "Download", which POSTs to `/api/upstream/download` and returns a short-lived (~1hr) signed Supabase Storage URL that can be fetched directly.
- Recharts' `<Pie>` v3.9.2 can render `.recharts-pie-sector` groups with an **empty `.recharts-shape` inside** (no `<path>` drawn, chart looks blank) when `isAnimationActive` is left at its default (`'auto'`) — the animation gets stuck at its zero-state in this dev environment. Fix: pass `isAnimationActive={false}` explicitly on `<Pie>`.
- **"Elegant" pass on the KPI tiles** (per user request, same day): `KPI_CARD_CLASS` gained a restrained `border-t-2 border-t-mari-navy` top accent (color as a quiet accent line, not a loud card fill), and the header gained a matching `border-b-2 border-mari-green` accent line. The paired big numbers inside `FuelComboTile`, `GasComboTile`, and `OilImportsTile` (previously alternating `text-mari-green`/`text-mari-blue` per value, e.g. Petrol green vs. HSD blue) were unified to a single `text-mari-navy` ink color — color is now reserved for things that carry real signal (up/down deltas, the "Total" rows in `QuarterReceivablesTile`/`ImfProgramTile`) rather than decorating every number. Small caps labels (e.g. "Petrol", "Crude Oil", tile header labels) softened from `font-semibold`/`tracking-wide` to `font-medium`/`tracking-wider` for a lighter, less shouty feel.

## Notes

- **`OIL_PRICE_OUTLOOK`** (`app/page.tsx`, rendered by `OilPriceOutlook` in the "6-Month Oil Price Outlook" detail panel): deliberately built as bear/base/bull **scenario ranges**, not a single point forecast — the user originally asked for a model to "forecast oil prices for next 6 months... as accurate as possible," which was declined as stated (a fabricated point forecast presented confidently on a business dashboard would be financial-advice-adjacent and misleadingly precise for something this uncertain, especially mid-conflict). Instead this is a synthesis of publicly published third-party forecasts (EIA STEO, World Bank, Goldman Sachs, JPMorgan) plus current news on the Iran-Hormuz conflict, framed explicitly as "not a prediction" with a visible disclaimer. Update by hand periodically by re-reading current news and forecaster updates — there's no API for this and the situation is moving fast (EIA's own STEO swung from $57.69 to $96 to $81.91 average-2026 across three consecutive monthly editions in 2026 alone, each overtaken by the next escalation/de-escalation). Before updating, re-verify the Hormuz conflict status against the live Hormuz badge (`/api/hormuz-status`) and recent news — don't let the scenario narrative drift out of sync with the dashboard's own live status indicator.
- PSO prices are OGRA-notified and only change roughly twice a month (1st/16th), so the chart will look flat between changes — that's expected, not a bug.
- The scraper is regex-based against PSO's current HTML structure (`<td>PREMIER EURO 5</td><td>Rs.316.15/Ltr</td>` style rows). If PSO redesigns their site, `extractPrice`/`extractEffectiveDate` in `app/api/oil-prices/route.ts` will need updating.
- OGRA issues Mari wellhead price notifications twice a year (Jan-Jun / Jul-Dec) as scanned PDF gazette notices addressed to Mari Energies Limited, split into a benchmark/normal price (Rs./MMBTU) and an incremental price (US$/MMBTU). As of 2026-07-22 the verified figures are the Jan-Jun 2026 notification (OGRA-Fin-28-9(85)/2015, dated Mar 30 2026): benchmark PKR 490.3733/MMBTU, incremental USD 5.3724/MMBTU, for Mari HRL & Mari Deep (Goru-B). OGRA's site had no "July to December 2026" section yet at that date. Don't guess these figures from press coverage — older articles cite a different Tier-1/Tier-2 fertiliser-feed-gas pricing mechanism that isn't the same number.
- `RECEIVABLES_BY_QUARTER` (Q1-Q3 FY2025-26 so far) comes from the "Transactions and balances with related parties" note in Mari's standalone quarterly reports (marienergies.com.pk/investors-relations/financial-reports) — same PDF-read-by-hand pattern as the Mari gas price. Refineries = Pak Arab Refinery + Pakistan Refinery; Others = Fauji Fertilizer + Foundation Power + Foundation Gas + Central Power Generation + non-related-party "due from others".
- `OIL_IMPORTS_LAST_MONTH` comes from OCAC's own Import/Export report (ocac.org.pk/oil-industry-statistics, currently a PDF like `Import-Export-2025-26-Jul-May.pdf` — filename shifts as months are added, no fixed URL), which is the only primary source with real per-month tonnage (news articles only report cumulative fiscal-year-to-date figures). It lags ~1 month behind the calendar. Pakistan's LNG import volume has no equivalent structured source — just scattered news mentions of individual cargo counts — so it's intentionally left off the dashboard for now.
- `IMF_PROGRAM` comes from the IMF's Pakistan Staff Report PDF (imf.org/en/countries/pak, mirrored at finance.gov.pk/mefp/) — specifically Tables 8a/8b ("Schedule of Reviews and Purchases/Disbursements"), which list every review's *test date* (tied to performance-criteria data) and SDR amount for the full 37-month EFF + 28-month RSF program. Test dates are not disbursement dates — actual Board approval has historically landed ~7-8 weeks after the test date (3rd review: test date Mar 15 2026, actual approval May 8 2026). Update this constant by hand whenever a new IMF review completes.
- Deliberately not built: "oil/LNG currently in transit to Pakistan." No free public API exists for this — it's what Kpler/Vortexa charge for. Free tools (TankerMap, MarineTraffic, VesselFinder) are interactive-map-only with no public API, so there's no reliable way to turn this into a daily-updating number without scraping something fragile/against ToS.
- `OILPRICEAPI_KEY` (in `.env.local`, gitignored) authenticates to OilPriceAPI with an `Authorization: Token <key>` header (not `Bearer`). Commodity codes used: `DUBAI_CRUDE_USD` (Gulf benchmark — more relevant to Pakistan's actual crude sourcing than Brent/WTI) and `JKM_LNG_USD` (Platts Japan-Korea-Marker, the global spot LNG benchmark). OilPriceAPI has no Arab Light code at all — it's not a spot-traded price, it's Saudi Aramco's Official Selling Price (OSP), announced once a month, not continuously.
- oilprice.com's `/oil-price-charts/` page lists **two different "Arab Light" rows** — `data-id='4402'` (under "OPEC Members (Daily Pricing)", a daily market estimate, `~13-Hour Delay`) and `data-id='30'` (under "OPEC Members (Monthly Pricing)", the actual Aramco OSP, `~24-Day Delay`, big jumps between updates). `app/api/global-oil-benchmarks/route.ts` deliberately uses `4402` for the "Arab Light" tile. Don't switch it to `30` — that's the monthly OSP, not a daily price, and the two numbers can differ by $8-10/barrel.
- The "PSX Announcements" tile was asked to update "daily at 9:30 AM and 3:30 PM", and the "PPIS Sector News" tile "daily at 9 AM" — the dashboard has no clock-triggered refresh mechanism (every other feature just polls on a fixed `setInterval`), so both were implemented as hourly polling (`PSX_ANNOUNCEMENTS_POLL_INTERVAL_MS`/`PPIS_NEWS_POLL_INTERVAL_MS` in `app/page.tsx`) plus a matching `revalidate: 3600` on their server routes, which naturally covers those times without needing new architecture. If literal clock-time-triggered refreshes are ever wanted, that's a different mechanism (e.g. a cron-triggered rebuild) than anything else on this dashboard uses.
- **The Hormuz status badge's source (straits.live) is an unofficial third-party tracker, not a governmental authority.** As of 2026-07-24, U.S. CENTCOM publicly states the Strait is "open to all vessels," while Iran's IRGC claims it's closed — straits.live's own verdict is explicitly qualified "by carrier posture" (i.e. actual transit volume — 15 ships/day on Jul 19 vs. ~88/day normal — rather than either government's claim). Treat the badge as a informed real-time proxy for shipping activity, not an authoritative legal/military status. If straits.live goes down or changes its page structure, consider UKMTO or CENTCOM advisories as alternate sources, though neither publishes a simple machine-readable open/closed flag.
- **`ogra.org.pk` may no longer be OGRA's real domain.** As of 2026-07-24, fetching it returns a page with a meta description reading "Independent informational website providing explanations, updates, and analysis about OGRA regulations..." and an HTML comment saying "use your own icon, NOT OGRA logo" — this reads like a lapsed/hijacked domain or a botched migration, not the official Oil & Gas Regulatory Authority government site. This is why `/api/mari-gas-price`'s OGRA status check may return "NONE FOUND" even when a real notification exists. Treat anything scraped from this domain as unverified until OGRA's actual current domain is confirmed independently — don't extract "data" from it and present it as authoritative.
- The UI theme (colors in `app/globals.css` as `--mari-navy`/`--mari-green`/`--mari-blue`/`--mari-gray-*`, header/footer/badge/card styling in `app/page.tsx`) was reskinned to match marienergies.com.pk's branding (dark navy header, brand green/blue accents, pill-shaped buttons). The header logo hotlinks `https://www.marienergies.com.pk/wp-content/themes/digitz/dist/img/logos/mari-energies.png` directly from their site rather than a local copy.
- No hosting decided yet; running locally via `npm run dev` for now.
- The project lives inside a OneDrive-synced folder, which Next.js flags as a "slow filesystem" (dev server benchmarks ~600ms vs. typical <100ms on a local disk). It still works, but if dev server performance becomes annoying, consider excluding `node_modules` and `.next` from OneDrive sync, or moving the project to a local (non-synced) folder.
- Node.js was installed system-wide via `winget install OpenJS.NodeJS.LTS`. If a fresh shell can't find `node`/`npm`, it's a PATH-refresh issue — open a new terminal window.
